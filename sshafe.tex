\begin{abstract}
Remote server administration over SSH remains one of the most routine operations across cloud platforms, enterprise infrastructure, and embedded systems. However, SSH has significant shortcomings when it comes to detecting attacks and credential rotation for compromised user accounts. This study focuses on covering both, delivering a real-time attack detection system and novel cryptographic password rotation flow. A real-time attack detection system based on time series analysis of the authentication logs followed by locking out accounts under attack ensures a fail-closed system whereas a novel cryptographic password reset flow involving ECDHE in WebAuthn mitigates attacks involving sessions during password rotation.

\end{abstract}

\section{Introduction}
While SSH supports both public-key and password-based authentication, passwords continue to dominate in practice because they allow users to connect from any machine, not just those that carry a private key. This convenience comes at a cost. Passwords are a natural target for automated attacks where adversarial tools cycle through vast credential lists at high speed until one combination succeeds. The standard defensive response, blocking an IP address after a threshold number of failed login attempts, is fundamentally flawed. Attackers have learned to slow down or spread their activity across multiple IP addresses, staying just under whatever detection limit is in place. This leaves a significant, well-documented gap between what rule-based tools like Fail2Ban can detect and what real-world attackers do.

The complexity of this problem lies in post-detection. Most systems respond by locking the targeted account and directing the user through a recovery flow that relies on email links, one-time passwords sent by SMS, or similar out-of-band verification mechanisms. These approaches introduce a fresh set of vulnerabilities: Email-based recovery links can be phished, OTPs be intercepted, etc. The session tokens used to maintain the binding between the person who authenticated and the person entering the new password are frequently misconfigured, long-lived, or exposed to CSRF attacks. Detection and recovery are two halves of a problem that existing solutions address poorly in isolation and rarely in combination which this study aims to solve.

\section{Methodology}

SSHafe addresses both halves together. The system is built around a machine learning model that reads directly from the Linux authentication log, the file that records every login attempt, outcome, username, and timestamp on a running server. Rather than working with raw network packet data, which is indirect and often strips away important application-level context, SSHafe works with the real-time authentication events themselves. This gives the system access to information such as login outcomes, targeted usernames, which are precisely the signals that distinguish a brute-force campaign from normal human behavior.

The model is trained using a sliding window approach across time scales of 30, 60, and 300 seconds. At each window, the system extracts feature like attempt rate, failure ratio, unique users in window, inter-arrival time (IAT), etc., that capture the behavioral signature of an attack and how tightly packed the attempts were in time (measured through inter-arrival time statistics). Brute-force attacks produce a recognizable pattern at this level of analysis: attempt rates spike sharply, failure ratios are high, inter-arrival times are very short, and automated tools often sweep across many usernames. Normal human login behavior, by contrast, is slower and almost always involves a single username per session.

A Light Gradient Boost Machine (LightGBM) classifier was trained on the features. The model was evaluated on a labeled SSH anomaly dataset and achieved a detection accuracy of 99.96\%, a precision of 100\%, and an F1-score of 0.9998. To ensure these results reflect genuine generalization rather than an artifact of a particular data split or random initialization, it was subjected to 5-fold cross-validation and retrained across 20 different random seeds. The results were consistent across all configurations, with essentially zero variance, indicating that the decision boundary the model has learned depends entirely on the discriminative temporal features rather than any stochastic aspect of training. The model was also empirically validated against unlabeled authentication logs from four real cloud virtual machines confirming its behavior on real-world traffic.

Deployment was carried out on a low-specification Azure virtual machine running Ubuntu 24.04, with only 2 virtual CPUs and 1 GB of memory, to establish that the system does not require significant compute resources. A daemon continuously monitors the authentication log and, upon detecting a brute-force attack against a valid user account, takes two immediate actions: it modifies the SSH server configuration to disable password authentication specifically for that account, blocking further attempts without disrupting other users and injects a banner into the SSH connection for that user, informing them that their account has been secured and providing a link to a password reset portal. In testing with the Hydra brute-force tool and the Rockyou password list, the system detected and suppressed attacks within ten seconds across all fifteen trials, even when the targeted account used a deliberately weak password. The virtual machine was subsequently left running in the cloud for two weeks and was discovered and attacked by real adversarial actors, against whom the system also successfully defended.

The password reset portal implements a novel credential rotation workflow that addresses the binding problem that undermines most existing recovery mechanisms. Instead of separating authentication from password entry and bridging the two with a session cookie or token, SSHafe encapsulates the new password inside the WebAuthn \cite{webauthn} assertion itself using an ECDHE exchange. The relying party generates ECDHE material and embeds the public part in the authentication challenge. The user's browser generates its own ECDHE material, derives a shared secret, and uses it to encrypt the new password with AES-GCM-256 before the WebAuthn assertion is signed and submitted. The server verifies the assertion signature against the user's registered passkey, then decrypts the password from the modified challenge field. The AEAD tag in AES-GCM defeats replay attacks. The username was derived from the resident credential passkey rather than user input which ensures the flow cannot be triggered by cross-site request forgery. There is no session to hijack, no cookies to steal, and no email channel to compromise. Authentication and password change occur as a single cryptographically bound operation. \section{Conclusion}

SSHafe provides a complete, end-to-end framework for defending SSH services against automated credential attacks. It closes the detection gap left open by rule-based systems and replaces a vulnerable recovery process with one that is phishing-resistant, session less, and cryptographically verifiable from start to finish. A 99.96\% validation accuracy as well as letting a public VM run exposed to real world attackers proves the merit of the study and that it is a viable approach for enterprise deployments.
